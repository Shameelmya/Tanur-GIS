Fix local body borders/labels not rendering + upgrade maplibre-gl

Root cause (found by direct WebGL pixel/tile-cache inspection): every tile
maplibre-gl 4.7.1 tried to build for the dissolved local-body polygons came
back state="errored" (16 of 17 tiles) with zero rendered buckets - silently,
with no console error or map "error" event, so nothing about it was visible
except the missing shapes. Isolated the standalone geojson-vt and
@mapbox/geojson-rewind packages against the exact same GeoJSON in plain
Node.js and both processed it without issue, which points at a bug in how
maplibre-gl 4.7.1's own GeoJSON worker pipeline drove those libraries for
this polygon shape specifically, already superseded by fixes across the
5.x line (the geojson-vt worker was substantially reworked over that range,
including a full migration to a maplibre-maintained fork at 5.17.0).

- Upgrade maplibre-gl 4.7.1 -> 5.24.0. This alone fixes the bug: local body
  fills, borders and name labels now render correctly. No API changes were
  needed anywhere in the app (typecheck and build are clean).
- Add fixWinding() to the data pipeline (lib.mjs, using @turf/turf's rewind)
  and apply it to every Polygon/MultiPolygon output (wards, local_bodies,
  constituency, constituency_mask, water) as defence in depth - correct
  exterior-ring winding is required by the GeoJSON spec anyway, and this
  exact bug class (bad winding breaking polygon tiling) has recurred several
  times in mapbox-gl/maplibre-gl's history.
- Local body borders are now bolder (3-5.5px + white halo, up from
  2.2-4px) and fully opaque, per request.
- Search ranking: an exact or prefix match on a local body / ward name now
  outranks a place that merely contains that word (e.g. searching
  "Ponmundam" now surfaces the Ponmundam panchayat itself ahead of a
  "Ponmundam ..." place), so searching a local body's name reliably zooms
  to and highlights that local body in its own colour.
